v1.8.18

2026년 8월 7일

ui-admin 릴리즈 노트 (v1.8.18)​

버그 수정​

  • RangeDatePicker에서 allowInput으로 날짜를 직접 타이핑할 때 onDateValidation이 호출되지 않던 문제를 수정하였습니다. (#410)
    • 날짜 입력이 완성되는 즉시 콜백이 호출됩니다. 종전에는 입력란을 벗어날 때까지 기다렸고, 그 사이 화면이 다시 그려지면 입력값이 사라져 검증이 돌지 않았습니다.
    • 구분자 없이 8자리(20260301)로 입력하는 경우에도 동작합니다. 종전에는 이 경로에서 콜백이 전혀 호출되지 않았습니다.
    • 마우스로 캘린더 바깥을 클릭해 입력을 마치는 경우도 포함합니다. 종전에는 Enter나 Tab으로 마칠 때만 동작했습니다.
  • validationOption.setting을 전달하지 않아도 종료일이 시작일보다 앞설 때 onDateValidation이 호출되도록 수정하였습니다.
    • 시작일 쪽은 setting 유무와 무관하게 검증하고 있어 두 방향의 동작이 달랐습니다.
    • "종료일이 오늘이면 검증을 건너뛴다"는 기존 예외는 기간(period) 검증에만 적용되도록 범위를 좁혔습니다.
  • 검증 콜백을 받은 사용처가 날짜를 되돌린 뒤, 사용자가 같은 날짜를 다시 입력하면 콜백이 호출되지 않던 문제를 수정하였습니다.
    • 같은 값의 중복 통지를 막는 판정이 부모의 값이 갱신된 뒤에도 남아 있어, 두 번째 입력부터 "이미 통지했다"고 잘못 판단하던 문제입니다.
  • 검증 콜백을 받은 사용처가 날짜를 되돌리면 입력란의 포커스가 빠지던 문제를 수정하였습니다.
    • 알림을 닫고 이어서 입력하면 키 입력이 들어가지 않아, 콜백이 호출될 때와 안 될 때가 있는 것처럼 보이던 문제입니다.
    • 화면이 다시 그려질 때 내부적으로 입력란이 DOM에서 이동하면서 포커스가 풀리던 것이 원인입니다. 이동 전 포커스 상태를 복원합니다.
  • DatePicker에서 enableTime을 사용할 때 날짜와 시간을 한 글자씩 입력하면 입력값이 사라지던 문제를 수정하였습니다.
    • 시(hour)의 첫 자리를 입력하는 순간 이전 값으로 되돌아가고, 이후 입력이 그 값에 덧붙어 잘못된 값이 되던 문제입니다.
    • 입력 완성 여부를 dateFormat 기준으로 판정하도록 바꿨습니다. 시간만 선택하는 noCalendar 모드(H:i)의 직접 입력도 함께 정상 동작합니다.

Breaking Changes​

  • onChangeDate가 같은 값으로 두 번 호출되지 않습니다.
    • 캘린더에서 같은 날짜를 다시 선택하면 종전에는 콜백이 또 호출됐습니다. onChangeDate는 날짜가 바뀌었을 때의 콜백이므로, 값이 같으면 호출하지 않도록 정리하였습니다.
    • 날짜 선택마다 부수 동작을 수행하고 있었다면 확인이 필요합니다.
  • onDateValidation은 이미 역전된 범위로 화면이 처음 그려질 때 type: 'start'와 type: 'end'로 각각 호출됩니다.
    • 두 호출의 newDate는 서로 반대편 날짜이므로, 양쪽을 모두 반영하면 시작일과 종료일이 뒤바뀝니다. 한쪽만 처리해야 합니다.
    • validationOption.setting을 전달하는 사용처에서는 종전부터 동일하게 동작했습니다. 이번 수정으로 setting을 전달하지 않는 사용처도 같은 동작이 됩니다.

리팩토링​

  • DatePicker가 부모에게 날짜를 통지하는 경로를 하나로 통합하였습니다.
    • flatpickr는 값을 확정하는 경로가 캘린더 선택·Enter·타이핑·바깥 클릭으로 4개인데 서로의 실행을 알지 못해, 통지 로직이 흩어져 있으면 경로가 늘 때마다 같은 결함이 재발합니다.
    • min/max 위반 판정도 단일 소스로 통일하여, 부모가 minDate/maxDate를 바꿨을 때 입력 경로와 선택 경로의 판정이 갈리지 않도록 하였습니다.

v1.8.17

2026년 7월 28일

ui-admin 릴리즈 노트 (v1.8.17)​

신규 기능​

  • ImageFileInput에 서버에 저장된 이미지의 미리보기 기능을 추가하였습니다. (#390)
    • uploadedFiles(ImageUploadedFile[] = { fileName, fileImageUrl })로 저장된 이미지를 전달하면 URL을 그대로 렌더링합니다. File로 변환할 필요가 없고, 외부 도메인 주소여도 fetch나 CORS 설정이 필요하지 않습니다.
    • 저장된 이미지가 새로 선택한 파일보다 앞에 표시되며, maxFileCount는 두 목록을 합해서 계산합니다.
    • value/onChange와 동일한 controlled prop입니다. 삭제 시 남은 목록으로 onUploadedFilesChange가 호출되며, 이 콜백을 전달하지 않으면 삭제가 반영되지 않습니다.
    • 저장된 이미지와 파일명이 같은 파일을 선택하면 ALREADY_UPLOADED로 반려합니다. 단 maxFileCount={1}은 교체 용도이므로 같은 이름도 허용하며, 새 파일을 선택하면 저장된 이미지를 함께 비웁니다.
    • ImageFileInputErrorType을 ImageFileInput에서도 재export하여, FileInput을 경유하지 않고 참조할 수 있습니다.
  • FileInput에 내장 파일 태그 목록의 노출을 제어하는 showFileTags prop을 추가하였습니다. (#384)
    • 기본값은 true로 기존 동작을 유지합니다. showFileTags={false}로 끄면 파일 목록을 원하는 위치·형태로 직접 렌더링할 수 있으며, 이때도 onChange/onFileSelect 콜백과 중복·개수·용량 검증은 그대로 동작합니다.
    • 내장 목록을 끄면 삭제 UI도 함께 사라집니다. DES-SPEC-012는 업로드된 파일의 삭제 기능을 필수로 요구하므로 삭제 수단을 직접 제공해야 합니다.
    • React 전용 prop입니다. HTML 버전은 원래부터 파일 태그를 렌더링하지 않고 onChange로 파일만 전달합니다.

기능 개선​

  • data-grid composition 개선 및 checkbox indeterminate CSS-native 수정 (#387)
    • renderToHtml 네이티브 HTML 태그(div/span/strong) 지원 및 sanitize allowlist 적용
    • data-grid composition 평면화 — summary/action-bar 구조 정정, select-box → select 교체
    • DnD with selectable: 액션바 이동 버튼·드래그셀 SVG 완성, --left modifier 등록
    • checkbox indeterminate :has(input:indeterminate) CSS-native 지원으로 CDN 환경 미적용 수정

버그 수정​

  • FileInput·ImageFileInput 이미지 미리보기의 object URL 누수를 수정하였습니다.
    • 렌더링 중 URL.createObjectURL을 호출하여 리렌더링마다 blob URL이 새로 생성되고 해제되지 않던 문제입니다. useObjectUrl 훅으로 분리하여 파일이 바뀌거나 언마운트될 때 URL.revokeObjectURL로 해제합니다.
    • 이 훅은 패키지 루트에서 export되므로 직접 사용할 수도 있습니다.
  • ImageFileInput이 disabled 상태에서도 미리보기 삭제 버튼을 노출하여 삭제가 가능하던 문제를 수정하였습니다.
    • DES-SPEC-013 §5.3에 따라 썸네일은 그대로 유지하고 삭제 아이콘만 미노출합니다. 저장된 이미지와 새로 선택한 파일 모두에 적용됩니다.
  • ImageFileInput에서 선택한 파일이 전량 반려될 때 기존 선택이 사라지던 문제를 수정하였습니다.
    • maxFileCount={1}인 영역에서 모든 파일이 반려되면 빈 목록으로 덮어써지던 문제입니다. 통과한 파일이 없으면 기존 선택과 저장된 이미지를 그대로 유지합니다.
  • ImageFileInput 문서의 HTML 옵션 표에 실제로 존재하지 않는 showImagePreview, checkboxName 옵션이 기재되어 있던 문제를 수정하였습니다.

    • HTML Tooltip에 forceVisible/panelClassName 옵션이 추가되어 React Tooltip API와 정렬되었으며, 툴팁이 hover 외에 키보드 포커스에서도 표시됩니다.
  • 툴팁 패널이 viewport 경계 보정으로 밀렸을 때 화살표가 앵커(아이콘)를 가리키지 못하던 문제를 수정하였습니다 (React·HTML 공통).
    • 화살표 오프셋을 --ncua-tooltip-arrow-x CSS 변수로 전달하며, 미설정 시 기존 중앙(50%) 동작이 유지됩니다.

    • controlled 컴포넌트로 동작합니다. activeTab 으로 현재 컨텍스트를 지정하고 onTabChange 로 선택을 처리합니다.
    • 콘텐츠 영역만 전환하는 HorizontalTab 과 달리, 컨텍스트(scope) 자체를 바꾸며 데이터 재로드를 동반합니다.
    • 현재 React 전용 컴포넌트로, HTML/CDN(바닐라 JS) 버전은 제공하지 않습니다.

버그 수정​

  • ComboBox · SelectBox(HTML) 단일 선택 모드에서 드롭다운이 열린 채 updateOptions() 호출 시 닫히던 문제 수정 검색·전체 조회·무한 스크롤 등 API 응답을 옵션에 반영하는 흐름에서, 옵션 갱신이 사용자 선택으로 오인되어 "선택 후 닫기" 분기가 실행되던 것이 원인. 선택값이 실제로 변경된 경우에만 통지하도록 수정하고, 내부 이중 갱신도 함께 제거. (React 구현체는 해당 없음)
