v1.8.21

2026년 9월 10일

ui-admin 릴리즈 노트 (v1.8.21)​

신규 기능​

  • 주소 찾기(우편번호 검색) 모달 PostcodeSearchModal을 추가하였습니다. (#464)
    • 검색어를 입력해 도로명·지번 주소를 찾고 하나를 선택하는 모달입니다. 검색 도움말은 PostcodeSearchModal.Tip으로 함께 제공합니다.
    • 주소 검색 API는 내장되어 있지 않습니다. 검색어·결과·총 건수·현재 페이지·로딩·오류 코드는 모두 사용처가 소유하는 controlled prop이며, 컴포넌트는 onSearch·onPageChange·onSelect·onSearchQueryChange로 시점만 알려줍니다.
    • 결과 선택 상태는 컴포넌트가 내부에서 관리하므로 선택값을 되돌려줄 필요가 없습니다. 모달을 다시 열면 초기화됩니다.
    • 오류 안내는 errorCode(E0006·E0008·E0009~E0013)로 지정합니다. 문구 자체를 넘기는 방식은 지원하지 않으며, 코드에 따른 문구와 인풋의 오류 표시는 컴포넌트가 처리합니다.
    • 한 페이지는 기본 15건(pageSize)이며, 검색 결과가 30건을 넘으면 검색 조합 안내가 검색 영역에 함께 노출됩니다.
    • React 전용입니다. HTML(CDN) 버전은 제공하지 않습니다. MCP(@ncds/ui-admin-mcp)에서는 조회할 수 있습니다.
  • Input의 trailingElement에 텍스트 슬롯을 추가하였습니다.
    • trailingElement={{ type: 'text', text: 'px' }} 형태로 단위 표시를 붙일 수 있습니다. leadingElement의 텍스트 슬롯과 좌우가 대칭입니다.
    • 종전에도 값을 넘기면 화면에 나오기는 했으나 타입 오류였고, leading 쪽 클래스가 붙어 테두리 없는 텍스트가 입력 영역에 겹쳐 보였습니다.
  • Callout Notification에 width prop을 추가하였습니다. (#466)
    • 'full'은 100%, 'fit'은 내용 폭(최대 100%)입니다. 지정하지 않으면 종전과 같이 100%입니다.

기능 개선​

  • Notification message 타입의 크기와 스타일을 축소하였습니다. (DES-SPEC-027, #457)
    • 여백·모서리·그림자·글자 크기가 전반적으로 작아지고, 아이콘과 버튼 배치가 조정되었습니다. type="message"를 사용하는 화면은 별도 조치 없이 모습이 바뀝니다. 구체적인 변경 내용은 아래 Breaking Changes를 확인해 주세요.
  • Notification에 hidePermanentlyLabel prop을 추가하였습니다.
    • onHidePermanently를 지정했을 때 노출되는 "다시 보지 않기" 문구를 바꿀 수 있습니다. 종전처럼 DOM을 직접 찾아 문구를 덮어쓰던 방식도 계속 동작합니다.
  • Notification 액션 버튼의 hierarchy 어휘를 secondary·secondary-gray·text·text-gray 네 가지로 통일하였습니다.
    • HTML(CDN) 버전에서 쓰던 link·link-gray는 deprecated로 남겨 두었고, 내부에서 text·text-gray로 자동 변환되므로 기존 코드는 그대로 동작합니다.
  • MCP에서 Callout Notification을 정적 마크업으로 렌더하도록 하였습니다. (#472)
    • render_to_html('notification', { type: 'callout' })이 CDN 초기화 스크립트 대신 정적 HTML을 반환합니다. Callout은 원래 JS API로 생성할 수 없는 타입이라, 종전에는 "JS가 필요하다"는 응답과 실제 마크업이 어긋나 AI 에이전트에게 잘못된 신호를 주고 있었습니다.
    • Callout을 언제 쓰는지, message 타입과 어떻게 구분하는지, 동적 문구를 넣을 때 주의할 점을 MCP 지침에 추가하였습니다.

버그 수정​

  • controlled Input(값을 value prop으로 내려주는 경우)에서 한글 조합이 중간에 끊기던 문제를 수정하였습니다.
    • 입력할 때마다 내부 상태를 갱신하고 있어, 그 리렌더가 한글 조합 도중에 끼어들어 조합이 깨지던 문제입니다.
    • controlled일 때는 value의 길이로 바로 계산하도록 바꿔 리렌더가 발생하지 않습니다. 글자 수 표시(showTextCount)는 종전과 같이 동작합니다.
  • PasswordInput의 자물쇠 아이콘이 값을 입력해도 연한 회색에 머물던 문제를 수정하였습니다. (#440)
    • 값의 유무를 value prop으로 판단하고 있어, value를 내려주지 않는 uncontrolled Input에서는 항상 "값 없음"으로 처리되던 문제입니다.
    • 값 유무를 실제 입력 요소에서 판단하도록 바꿔, 입력했거나 포커스된 상태에서 아이콘이 진해집니다.
  • PasswordInput이 비활성 상태일 때 비밀번호 표시 토글 버튼이 그대로 보이던 문제를 수정하였습니다.
  • 좁은 컨테이너에서 Notification message의 텍스트가 한 글자씩 세로로 쪼개지던 문제를 수정하였습니다. (#450)
    • 반응형 처리가 뷰포트 폭 기준이라, 화면은 넓고 컨테이너만 좁은 어드민 레이아웃에서는 발동하지 않던 문제입니다. 폭 290px 기준으로 높이가 1018px까지 늘어났습니다.
    • 텍스트 영역에 최소 폭과 줄바꿈을 주어 같은 조건에서 162px로 정상 표시됩니다. 600px 이상에서는 종전과 같은 한 줄 배치입니다.
  • 모바일 Pagination에서 이전·다음 버튼이 나오지 않던 문제를 수정하였습니다.
    • breakPoint="mo"는 페이지 번호 목록과 처음·마지막 버튼을 숨기므로 이전·다음이 유일한 이동 수단인데, 버튼 노출 조건이 PC 기준이라 페이지 수가 적으면 이동 수단이 하나도 없는 상태가 되었습니다.
    • 모바일에서는 페이지가 2개 이상이면 이전·다음이 노출됩니다. PC 동작은 종전과 같습니다.
  • HTML(CDN) 버전 Notification에서 액션 버튼에 hierarchy를 지정하지 않으면 onClick이 호출되지 않던 문제를 수정하였습니다.
    • 버튼을 그릴 때와 이벤트를 연결할 때 서로 다른 규칙으로 키를 만들고 있어 연결이 어긋나던 문제입니다.
  • MCP를 통해 HTML을 작성할 때 Input 단위 텍스트의 테두리와 모서리가 사라지던 문제를 수정하였습니다.
    • 클래스명을 문자열 조합으로 만들면서 MCP가 완성된 클래스명을 수집하지 못해, 검증 단계에서 해당 요소가 제거되던 문제입니다. React 컴포넌트를 직접 쓰는 경우에는 영향이 없었습니다.

Breaking Changes​

  • Notification message 타입의 크기·스타일·DOM 구조가 바뀌었습니다. (DES-SPEC-027, #457)
    • props는 그대로이지만 화면이 달라집니다. 여백 16px 24px → 12px 16px 12px 24px(모바일 16px → 12px 8px 12px 16px), 모서리 8px → 12px, 그림자 lg → md, 제목 글자 md → sm, 보조 텍스트 sm → xs, 좌측 아이콘 lg → md로 조정되었습니다.
    • "다시 보지 않기"와 닫기 버튼을 감싸는 영역이 액션 버튼 영역 안쪽으로 이동하였고, 표시할 내용이 없으면 해당 영역을 아예 그리지 않습니다. 또한 "다시 보지 않기"에 붙던 ncua-notification__action-button--link 수식자가 제거되었습니다.
    • Notification의 DOM 구조나 클래스명을 선택자로 잡아 스타일을 덮어썼거나 E2E 테스트를 작성한 화면은 확인이 필요합니다.
    • HTML(CDN) 버전의 message 액션 버튼 크기가 sm(36px)에서 xs(28px)로 바뀌어 React와 같아집니다. floating·full-width 타입은 종전과 같습니다.
  • Input의 슬롯 아이콘(leadingElement·trailingElement) 색상이 입력 상태를 따라갑니다.
    • 기본은 --gray-300, 값이 있거나 포커스된 상태에서는 --gray-600, 비활성 상태에서는 다시 --gray-300입니다.
    • color를 지정하지 않은 슬롯 아이콘에만 적용됩니다. 색을 고정하고 싶다면 color를 명시해 주세요.
  • Input의 루트 요소에 값이 있을 때 has-value 클래스가 붙습니다.
    • 아이콘 색상을 CSS로 판단하기 위해 추가된 클래스입니다. Input의 클래스 목록을 검사하는 테스트가 있다면 확인이 필요합니다.

문서​

  • SelectBox 문서에 옵션 아이콘 사용법을 추가하였습니다.
    • OptionType.icon은 드롭다운 목록과 선택 후 트리거 양쪽에 표시되며, SelectBox의 size와 무관하게 16px로 고정됩니다. multiple 모드에서는 트리거에 표시되지 않습니다.
    • 타입 표기도 실제 정의(SlotIconComponent)에 맞게 정정하였습니다.
  • Input 문서 예제에서 아이콘 크기와 색상을 하드코딩하던 부분을 제거하였습니다.
    • 컴포넌트 기본값과 다른 값이 예제에 박혀 있어, 문서를 보고 작성하면 실제와 다르게 보이던 문제입니다. 슬롯 아이콘의 상태별 색상 변화도 문서에서 확인할 수 있습니다.

v1.8.20

2026년 8월 13일

ui-admin 릴리즈 노트 (v1.8.20)​

버그 수정​

  • Input 계열 컴포넌트에서 clearText·onClearText를 사용하면 콘솔에 React의 알 수 없는 속성 경고가 출력되던 문제를 수정하였습니다. (#407)
    • 두 prop을 내부에서 꺼내 쓰지 않고 나머지 속성과 함께 DOM <input>으로 그대로 넘기고 있어, 브라우저가 모르는 속성으로 전달되던 문제입니다.
    • 두 prop을 내부에서만 사용하도록 분리하여 DOM으로 전달되지 않습니다. 화면 동작과 사용법은 종전과 같습니다.

문서​

  • ButtonGroup 인터랙티브 예제에서 실제로 존재하지 않는 label 컨트롤을 제거하였습니다.
    • ButtonGroupProps에 없는 값이라 컨트롤을 바꿔도 화면에 반영되지 않아, 사용할 수 있는 prop으로 오인할 수 있었습니다.
    • 컨트롤 순서도 단일 값(size·disabled·className·hasBorder) 다음에 배열(items)이 오도록 정리하였습니다.

v1.8.19

2026년 8월 11일

ui-admin 릴리즈 노트 (v1.8.19)​

버그 수정​

  • 세로형(vertical) 테이블에서 레이블 칸을 rowSpan으로 병합했을 때, 레이블이 생략된 행의 값 칸이 레이블과 같은 회색 배경으로 표시되던 문제를 수정하였습니다. (#422)
    • 레이블 스타일을 "그 행의 첫 번째 칸"이라는 위치 기준으로 적용하고 있어, 레이블이 병합되면 값 칸이 그 행의 첫 번째 칸이 되어 레이블 배경·고정폭·글자색을 함께 물려받던 문제입니다.
    • 레이블 판별 기준을 위치에서 칸의 종류(<th>)로 바꿨습니다. 값 칸은 <td>이므로 병합 여부나 위치와 무관하게 흰 배경을 유지합니다.
  • HTML(CDN) 버전에서 세로형 테이블의 레이블 칸이 <td>로 생성되던 문제를 수정하였습니다.
    • React 버전은 Table.Cell에 isHeader를 주면 <th scope="row">로 렌더되지만, HTML 버전은 <td>로 만들고 있어 두 버전의 결과가 달랐습니다.
    • HTML 버전도 React와 같은 구조를 만들도록 통일하였습니다. Table 클래스로 세로형 테이블을 생성하면 레이블 칸이 <th scope="row">로 나옵니다.
  • 세로형 테이블의 값 칸 안에 표를 중첩했을 때, 안쪽 표 첫 열의 글자색이 칸의 종류에 따라 달라지던 문제를 수정하였습니다.
    • 안쪽 표는 바깥 세로형 레이블 스타일을 물려받지 않도록 되돌리는 규칙을 갖고 있는데, 글자색만 그 규칙에서 빠져 있어 바깥 값이 흘러들어오고 있었습니다.
    • 안쪽 표 첫 열은 칸의 종류와 무관하게 본문 글자색을 사용합니다.

Breaking Changes​

  • 세로형 테이블의 레이블 칸은 <th>여야 레이블 스타일(회색 배경·고정폭·좌측 정렬)이 적용됩니다.
    • React는 <Table.Cell isHeader>, HTML은 <th scope="row" class="ncua-table__cell">로 작성해야 합니다.
    • 종전에는 위치만 맞으면 <td>도 레이블처럼 보였습니다. isHeader 없이 레이블 칸을 작성한 화면이 있다면 회색 배경이 사라지므로 확인이 필요합니다.
    • 문서에 안내되어 있던 사용법이며, MCP(@ncds/ui-admin-mcp)의 HTML 검증도 종전부터 <th scope="row">를 요구하고 있었습니다.

문서​

  • 세로형 테이블 문서에 예시 두 가지를 추가하였습니다.
    • 레이블 칸 병합(rowSpan) — 레이블 하나가 여러 행에 걸치는 경우
    • 값 칸에 표 중첩 — 값 칸 안에 다른 표를 넣는 경우
    • 두 경우 모두 React 문서와 HTML 플레이그라운드(playground/route/table.html) 양쪽에서 확인할 수 있습니다. HTML 버전의 Table 클래스는 컬럼 배열당 한 행을 만드는 구조라 rowSpan과 표 중첩을 옵션으로 표현할 수 없어, 직접 작성하는 마크업 형태로 안내합니다.
  • 시작하기 문서에 알파 버전 검증 방법 안내를 추가하였습니다. (#417)
    • 알파 버전 설치(@alpha) → 동작 확인 → 정식 전환 3단계와, 운영 배포 전 알파 버전이 물려 있지 않은지 확인하는 검사 예시를 담았습니다.

v1.8.18

2026년 8월 7일

ui-admin 릴리즈 노트 (v1.8.18)​

버그 수정​

  • RangeDatePicker에서 allowInput으로 날짜를 직접 타이핑할 때 onDateValidation이 호출되지 않던 문제를 수정하였습니다. (#410)
    • 날짜 입력이 완성되는 즉시 콜백이 호출됩니다. 종전에는 입력란을 벗어날 때까지 기다렸고, 그 사이 화면이 다시 그려지면 입력값이 사라져 검증이 돌지 않았습니다.
    • 구분자 없이 8자리(20260301)로 입력하는 경우에도 동작합니다. 종전에는 이 경로에서 콜백이 전혀 호출되지 않았습니다.
    • 마우스로 캘린더 바깥을 클릭해 입력을 마치는 경우도 포함합니다. 종전에는 Enter나 Tab으로 마칠 때만 동작했습니다.
  • validationOption.setting을 전달하지 않아도 종료일이 시작일보다 앞설 때 onDateValidation이 호출되도록 수정하였습니다.
    • 시작일 쪽은 setting 유무와 무관하게 검증하고 있어 두 방향의 동작이 달랐습니다.
    • "종료일이 오늘이면 검증을 건너뛴다"는 기존 예외는 기간(period) 검증에만 적용되도록 범위를 좁혔습니다.
  • 검증 콜백을 받은 사용처가 날짜를 되돌린 뒤, 사용자가 같은 날짜를 다시 입력하면 콜백이 호출되지 않던 문제를 수정하였습니다.
    • 같은 값의 중복 통지를 막는 판정이 부모의 값이 갱신된 뒤에도 남아 있어, 두 번째 입력부터 "이미 통지했다"고 잘못 판단하던 문제입니다.
  • 검증 콜백을 받은 사용처가 날짜를 되돌리면 입력란의 포커스가 빠지던 문제를 수정하였습니다.
    • 알림을 닫고 이어서 입력하면 키 입력이 들어가지 않아, 콜백이 호출될 때와 안 될 때가 있는 것처럼 보이던 문제입니다.
    • 화면이 다시 그려질 때 내부적으로 입력란이 DOM에서 이동하면서 포커스가 풀리던 것이 원인입니다. 이동 전 포커스 상태를 복원합니다.
  • DatePicker에서 enableTime을 사용할 때 날짜와 시간을 한 글자씩 입력하면 입력값이 사라지던 문제를 수정하였습니다.
    • 시(hour)의 첫 자리를 입력하는 순간 이전 값으로 되돌아가고, 이후 입력이 그 값에 덧붙어 잘못된 값이 되던 문제입니다.
    • 입력 완성 여부를 dateFormat 기준으로 판정하도록 바꿨습니다. 시간만 선택하는 noCalendar 모드(H:i)의 직접 입력도 함께 정상 동작합니다.

Breaking Changes​

  • onChangeDate가 같은 값으로 두 번 호출되지 않습니다.
    • 캘린더에서 같은 날짜를 다시 선택하면 종전에는 콜백이 또 호출됐습니다. onChangeDate는 날짜가 바뀌었을 때의 콜백이므로, 값이 같으면 호출하지 않도록 정리하였습니다.
    • 날짜 선택마다 부수 동작을 수행하고 있었다면 확인이 필요합니다.
  • onDateValidation은 이미 역전된 범위로 화면이 처음 그려질 때 type: 'start'와 type: 'end'로 각각 호출됩니다.
    • 두 호출의 newDate는 서로 반대편 날짜이므로, 양쪽을 모두 반영하면 시작일과 종료일이 뒤바뀝니다. 한쪽만 처리해야 합니다.
    • validationOption.setting을 전달하는 사용처에서는 종전부터 동일하게 동작했습니다. 이번 수정으로 setting을 전달하지 않는 사용처도 같은 동작이 됩니다.

리팩토링​

  • DatePicker가 부모에게 날짜를 통지하는 경로를 하나로 통합하였습니다.
    • flatpickr는 값을 확정하는 경로가 캘린더 선택·Enter·타이핑·바깥 클릭으로 4개인데 서로의 실행을 알지 못해, 통지 로직이 흩어져 있으면 경로가 늘 때마다 같은 결함이 재발합니다.
    • min/max 위반 판정도 단일 소스로 통일하여, 부모가 minDate/maxDate를 바꿨을 때 입력 경로와 선택 경로의 판정이 갈리지 않도록 하였습니다.

    • 저장된 이미지와 파일명이 같은 파일을 선택하면 ALREADY_UPLOADED로 반려합니다. 단 maxFileCount={1}은 교체 용도이므로 같은 이름도 허용하며, 새 파일을 선택하면 저장된 이미지를 함께 비웁니다.
    • ImageFileInputErrorType을 ImageFileInput에서도 재export하여, FileInput을 경유하지 않고 참조할 수 있습니다.
  • FileInput에 내장 파일 태그 목록의 노출을 제어하는 showFileTags prop을 추가하였습니다. (#384)
    • 기본값은 true로 기존 동작을 유지합니다. showFileTags={false}로 끄면 파일 목록을 원하는 위치·형태로 직접 렌더링할 수 있으며, 이때도 onChange/onFileSelect 콜백과 중복·개수·용량 검증은 그대로 동작합니다.
    • 내장 목록을 끄면 삭제 UI도 함께 사라집니다. DES-SPEC-012는 업로드된 파일의 삭제 기능을 필수로 요구하므로 삭제 수단을 직접 제공해야 합니다.
    • React 전용 prop입니다. HTML 버전은 원래부터 파일 태그를 렌더링하지 않고 onChange로 파일만 전달합니다.

기능 개선​

  • data-grid composition 개선 및 checkbox indeterminate CSS-native 수정 (#387)
    • renderToHtml 네이티브 HTML 태그(div/span/strong) 지원 및 sanitize allowlist 적용
    • data-grid composition 평면화 — summary/action-bar 구조 정정, select-box → select 교체

버그 수정​

    • DES-SPEC-013 §5.3에 따라 썸네일은 그대로 유지하고 삭제 아이콘만 미노출합니다. 저장된 이미지와 새로 선택한 파일 모두에 적용됩니다.

  • ImageFileInput 문서의 HTML 옵션 표에 실제로 존재하지 않는 showImagePreview, checkboxName 옵션이 기재되어 있던 문제를 수정하였습니다.
